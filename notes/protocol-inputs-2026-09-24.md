# Inputs for the lesson-plan protocol (2026-09-24)

Raw material for writing the protocol after reviewing the three pilots (Rasch,
CTT and reliability, factor analysis I). This is not the protocol; it records
what Ben asked for and what building the pilots taught.

## What Ben has asked for
- Interactive widgets wherever possible; a progression **widgets → simulations
  (webR, also downloadable) → empirical examples** (IRW data; we run them and
  give the code).
- Quizzes (self-check) and an "Ask Claude" link instead of an embedded bot.
- **Problems at the end of every lesson.**
- **Link IRW vignettes** where relevant (not embed).
- **A ceiling on the number of IRW tables** per lesson's empirical section.
- Proofs available but out of the main line (e.g. collapsible "why alpha is a
  lower bound").
- Written in **Ben's voice**.
- A first course: core lessons stay first-course level; deeper material is marked
  optional.
- Only tables with a **tokenless CSV** (landing page); larger ones need a
  teaching-subsample table.

## What the pilots settled or suggested

**Shape.** All three use the same section order: header box · What this is for ·
Goals · Core ideas (prose with "Try it" widgets and "Quick check" quizzes inline;
proofs in collapsible callouts) · Simulate · With real data · Problems · Ask Claude
· Going further · For instructors. The counts came out similar:

| | Widgets | Quizzes / predict | Tables | Problems |
|---|---|---|---|---|
| Rasch | 5 | 4 / 1 | 2 (chess_lnirt, wirs) | 6 |
| CTT and reliability | 3 | 2 / 1 | 2 (gilbert_meta_1, lessR_Mach4) | 6 |
| FA I | 3 | 3 / 1 | 1 (bfi2_zhang_2025) | 6 |

Candidate rules: 3–5 widgets; one quick check after each major idea; one
predict-then-check tied to the real data; **at most 2 tables** (a proposal for
the ceiling); about 6 problems (a derivation, the real data, a design or judgment
question, a challenge).

**The real-data section should find something.** Each pilot's empirical section
turned up a result that carries the lesson: an item that doesn't fit (Y15 in chess;
s_read_7_4 in gilbert_meta_1), keying you can't detect from the data (Mach IV, alpha
0.37 → 0.70), a "how many factors" answer (9) that differs from the design (5).
Candidate rule: choose tables for what they teach, and write the prose around the
actual output. Never assert a pattern the output doesn't show.

**Mechanics (the protocol should state these, so later lessons don't relearn them).**
- The code lives in `lessons/code/<id>-sim.R` and `<id>-irw.R` (single source,
  downloadable). The page includes the sim file into a webR cell and reads the irw
  file's `## ---- label` chunks with `knitr::read_chunk`.
- The first chunk of every lesson must `source("_course.R")`. It registers the knitr
  engine that passes `{webr}` cells through; without it, knitr silently drops the
  cells or strips `context: setup`.
- webR setup: lessons using mirt include `code/_webr-setup.R` (generated by
  `webr/build_repo.R`: stubs for mirai/qs2). Others install their own packages in a
  `context: setup` cell and must set `options(mc.cores = 1)`, because
  `parallel::mclapply` hangs in webR.
- Keep browser simulations small (seconds, not minutes) and say how to scale up
  locally.
- Math inside OJS `md` strings isn't typeset; use words there. Quiz text supports
  `$...$` (typeset by MathJax).
- Data: read version-pinned CSV URLs (from `irw_csv_url()`); drop all-missing
  respondents; check keying and waves before item analysis; get citations from
  IRW biblio (`get_citation`), not memory. Two of my first-draft citations were
  wrong.
- Render: `freeze: auto` caches the empirical results. A transient network failure
  during the first render happened once; a retry fixed it.
- Verification per lesson: render with no token; in a browser, confirm widgets
  respond, quizzes typeset, the webR cell runs and matches local R.

**Voice.** First person where there's a judgment ("my default is oblique", "the one
I would reach for first"). Verdict first, then rationale. Concrete anchors (chess,
Mach IV, a reading RCT). Hedges are graded adverbs. One wry aside at most.

## Open questions for Ben
1. Table ceiling: is 2 right, or 3 when a contrast needs it?
2. Problems: public solutions, instructor-only, or none? Several 252 problems were
   deliberately open ("I don't know the answer"); keep that genre?
3. Quizzes: are 3–4 per lesson right, or should they be denser?
4. Lesson length: the pilots run ~12,000–20,000 px rendered. Split long lessons,
   or accept them as a class session's worth?
5. "Ask Claude": the `claude.ai/new?q=` prefill has not been verified with a
   logged-in browser.
